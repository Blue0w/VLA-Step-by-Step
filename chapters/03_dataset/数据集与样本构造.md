# 第 03 章 · 数据集与样本构造

上一章，我们拆解了红杯实验里每一步发给机械臂的 7 维动作 `[dx, dy, dz, rx, ry, rz, gripper]`，也知道了模型既可以一次预测 1 步，也可以一次预测一小段长度为 `K` 的动作块。接下来要解决一个更实际的问题：**用来教模型模仿学习的训练样本，到底长什么样？我们怎样从一条完整的人类演示轨迹里，切出一个个可以喂给神经网络的训练样本？**

## 1. 从一条演示轨迹说起

在第 01 章里我们提到，LIBERO 的官方演示来自人类遥操作。操作员每次把红杯放到左盘或右盘，都会产生一条按时间排列的完整记录，叫作一条**轨迹（Trajectory）**。

如果一条演示一共持续了 `T` 个控制步（比如 `T = 150` 步），那么它就记录了从第 `0` 步到第 `T - 1` 步每一刻的：
- **相机看到了什么**（工作区相机、腕部相机画面）
- **机械臂当时在哪**（末端位置、朝向、夹爪开合等自身状态）
- **人类操作员发出了什么指令**（那 7 个动作数字）
- **这次任务要做什么**（一句自然语言指令，例如 `put the red mug on the left plate`）

如果把一条轨迹比作一段带操作按键录像的游戏实况，这一章要做的事情，就是把这段连续录像拆成一张张「当前画面 + 当前状态 + 任务目标 → 当时按下的动作」的训练卡片。

> [!NOTE]
> 为了方便直接查看结构，[本章 `media/` 目录](media) 预留了单条红杯任务演示样本（如 `demo_0`）的存放位置。由于完整 LIBERO-90 数据集体积较大且不包含在代码仓库中，运行 [本章实验](experiment.md) 时可以从官方数据集中单独抽取出一条轨迹放入 `media/` 进行离线观察。

## 2. LIBERO 数据集的文件格式：HDF5

LIBERO 官方演示使用 **HDF5（`.hdf5`）** 格式保存。你可以把一个 `.hdf5` 文件想象成一个**磁盘上的多层字典（或文件夹）**：最外层按「任务」分文件，文件里面按「轨迹」分文件夹，每条轨迹下面再存放各个模态的多维数组（NumPy 数组）。

以本教程的红杯任务为例，对应的官方演示文件分别是：
- `LIVING_ROOM_SCENE5_put_the_red_mug_on_the_left_plate_demo.hdf5`
- `LIVING_ROOM_SCENE5_put_the_red_mug_on_the_right_plate_demo.hdf5`

打开其中任意一个文件，内部的层级结构如下：

```text
LIVING_ROOM_SCENE5_put_the_red_mug_on_the_left_plate_demo.hdf5
└── data/
    ├── (文件/任务属性：语言指令、环境配置等)
    ├── demo_0/                        # 第 0 条演示轨迹（假设长度 T = 150）
    │   ├── actions                    # (T, 7)       float64，第 02 章讲的 7 维控制指令
    │   ├── states                     # (T, D_sim)   float64，MuJoCo 底层仿真状态（用于回放，不喂给模型）
    │   ├── rewards                    # (T,)         float64，每步奖励
    │   ├── dones                      # (T,)         uint8，是否到达任务结束步
    │   └── obs/                       # 观测数据（对应模型能看到的输入）
    │       ├── agentview_rgb          # (T, H, W, 3) uint8，工作区第三视角相机画面
    │       ├── eye_in_hand_rgb        # (T, H, W, 3) uint8，腕部相机画面
    │       ├── ee_pos                 # (T, 3)       float64，末端位置 (x, y, z)
    │       ├── ee_ori                 # (T, 3)       float64，末端朝向
    │       ├── gripper_states         # (T, 2)       float64，左右夹爪指位置
    │       └── joint_states           # (T, 7)       float64，7 个关节角度
    ├── demo_1/
    └── ...（通常每个任务有 50 条演示）
```

这里有三个细节需要特别留意：
1. **模型只能用「合理观测」，不能偷看答案**：`states` 里保存了桌子上杯子和盘子的精确物理坐标，它只用来在仿真器里复现画面，**绝不能**作为模型输入（真实世界里机器人并没有全局上帝视角坐标）。模型只能读 `obs/` 里的相机画面、自身状态和语言指令。
2. **语言指令是任务级别的**：在同一个 `.hdf5` 文件里，所有 `demo_i` 的每一帧都共享同一句任务指令。只有把「放左盘」和「放右盘」两个文件合在一起训练时，语言指令才真正起到区分目标的作用。
3. **图像像素与坐标方向**：LIBERO 官方导出图像是 `uint8`（`0–255`），后续进入视觉编码器之前需要转成浮点并归一化；此外注意区分图像坐标系与我们在 [第 01 章](../01_environment/仿真环境与演示数据.md) 提到的 OpenGL 翻转约定。

## 3. 把一条轨迹切成训练样本

假设我们选中了 `demo_0` 里的第 `t` 步，就可以构造出第 `t` 个训练样本：

### 情况 A：单步预测（`K = 1`）

```text
输入（Input）:
  - image:       obs/agentview_rgb[t]      形状 (H, W, 3)
  - state:       拼接末端位姿与夹爪状态       形状 (D_state,)
  - instruction: "put the red mug on the left plate"

监督标签（Target）:
  - action:      actions[t]                形状 (7,)
```

### 情况 B：动作块预测（Action Chunking，`K > 1`）

第 02 章提到，为了动作更连贯，VLA 常一次预测未来连续 `K` 步（例如 `K = 4` 或 `K = 8`）。这时标签变成切片：

```text
actions[t : t + K]   # 形状 (K, 7)
```

如果 `t` 已经快到轨迹末尾（例如总长 `T = 150`，当前 `t = 148`，而 `K = 4`），后面只剩 2 步怎么办？常见做法有两种，且往往一起使用：
- **边界填充（Padding）**：用最后一步的动作（或静止动作 `[0, 0, 0, 0, 0, 0, last_gripper]`）补齐到长度 `K`。
- **有效掩码（Action Mask）**：额外记录一个长度为 `K` 的布尔掩码 `[True, True, False, False]`，计算损失时只对真实存在的那几步求误差，或者在末端保持静止。

## 4. 数据划分与归一化：两个最容易踩的坑

拿到几十条轨迹并切成几千个样本后，千万不能直接像普通图像分类那样把所有帧混在一起随机打乱。

### 坑 1：必须「按完整轨迹」划分训练集和验证集

假设 `demo_0` 一共有 150 帧，第 40 帧和第 41 帧只隔了不到 0.05 秒，画面几乎一模一样。
- **错误做法**：把所有帧混在一起，随机抽 80% 做训练、20% 做验证。这样第 40 帧进了训练集、第 41 帧进了验证集，模型靠「背下几乎相同的画面」就能在验证集上拿到极低误差，却在真正换一个杯子初始位置时完全失效。
- **正确做法**：先按 `demo_id` 划分（例如 50 条轨迹里 40 条进训练集、10 条进验证集），再各自把轨迹切成单步或动作块样本。这样验证集测到的是**模型面对没见过的摆法时的泛化能力**。

### 坑 2：归一化统计量只能从「训练集」计算

动作向量里，前 3 维平移、中间 3 维旋转和第 7 维夹爪（`-1` 或 `+1`）的数值分布并不相同；机械臂状态里的末端位置（米）和夹爪关节位置（厘米级）量纲也不同。训练前通常会对动作和状态做标准化（减均值除以标准差）或缩放到 `[-1, 1]`。

- **统计量只能算在训练集上**：如果把验证集也混进去算均值和方差，相当于提前把验证集的分布信息泄漏给了模型。
- **保存统计量用于推理**：模型在测试时吐出的是归一化后的数字，在交给 `env.step()` 之前，必须用同一组训练集统计量做**反归一化**还原，否则控制器收到的动作范围会完全错乱。

## 5. 组装成批次（Batch）

在 PyTorch 训练循环里，DataLoader 会把 `B` 个相互独立的样本打包成一个批次（Batch）：

| 字段 | 单个样本形状 | 打包成 Batch 后的形状 | 说明 |
| --- | --- | --- | --- |
| `image` | `(H, W, 3)` | `(B, H, W, 3)`（或转成 `(B, 3, H, W)`） | 后续第 04 章做图像预处理与通道调整 |
| `state` | `(D_state,)` | `(B, D_state)` | 机械臂自身状态向量 |
| `action` | `(K, 7)` | `(B, K, 7)` | 未来 `K` 步动作块（单步时 `K = 1`） |
| `instruction` | `str` | 长度为 `B` 的字符串列表 | 后续第 05 章分词并转成 token 序列 |
